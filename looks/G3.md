## 1. What the evidence supports (read this first)

G3 has the thinnest PTDE evidence of any group. **No source describes a hue difference anywhere in G3**: nothing
supports a yellow-green Blighttown haze, a redder lava or a bluer Ash Lake. So colour casts are held at vanilla, on
the basis of the art intent, and no cast is invented. The written claims that do exist:

Opposed by: Steam (carbonfibre), Push Square, PTDE forum | medium, contested and display-dependent |
| DSR lights characters too strongly, with a whitish, sourceless sheen in dark areas | all, cited for Blighttown | Steam (Crocalu); DSRRL; mod 711; 5 sources on the player light | high (cross-source) |

| Lava reads flat at range without some bloom | Demon Ruins, Izalith | mod 711; YALO | low-medium |

**So G3 is a protect-and-refine group.** It makes five moves:
1. Lift Blighttown's crushed bottom end without brightening its mood.
2. Cut sourceless character sheen.
3. Cut the Catacombs' ambient fill slightly.
4. Never let lava lose its glow.
5. Turn the sun off in every cave.

There is no hue move and no darkening beyond about 0.35 EV anywhere.

## 2. Checks

**Standard stats** come from `stats.json` (HUD masked): `ev` (log2 geometric-mean luminance), p10/p50/p90/p99 (luma
0-255), `clip_pct`, `crush_pct` (luma <= 3), `mean_sat`, and `mid_oklab_a/b` (pixels with luma 40-200 only).

**Extra crops** use the same maths as `DsrInput.StatsJson` with step 2, computed on the 4K PNG:
- **CHAR** = x 1650-2210, y 880-1720. This is the `sun_ab` character box, cut off above the Rest-at-bonfire
  prompt. `char_ev` = log2 of mean linear Y.
- **ENV** = the full frame minus the HUD masks, the prompt box (1100-2720 x 1720-1900) and the character column
  (x 1600-2300). `env_ev` = log2 of mean linear Y.
- **d_char_env** = (char_ev new - vanilla) - (env_ev new - vanilla). Negative means the character now sits deeper
  in the scene. Noise is about 0.2 EV (sun_ab measured 0.18 vanilla-vs-vanilla), so judge it from 2 captures.
  It is not valid where a flame is inside the box (blighttown_bridge).

**Reading the stats in dark views.** When crush is above about 30%, the geometric-mean `ev` over-reacts to
blacks: a pixel lifted from luma 0 to 1 adds about 5 EV to its log term. So in crush-dominated views, use p50
(and p99 in the Tomb) as the exposure check, and read `ev` loosely. In the Tomb (crush 84-93%, mid_frac
0.04-0.09) `ev` sits on the 1e-5 floor and Oklab is noise. Those fields are not enforced there.

## 3. G3-wide rules

- **Darkening budget.** In `validate.py`, log2(cap_v/cap_m) x 2.8 must be <= 1, where cap = grayKeyValue / minAdaptedLum.
  So cap_m >= 0.78 x cap_v: minAdaptedLum can rise to x1.28 at most, or grayKey can fall to x0.78. Add the
  ambient band and the PLAN guardrails (+-0.3 EV; dark areas down to -0.8) and the realistic G3 floor is about
  -0.35 EV. No G3 evidence asks for more.
- **Hue is held.** mid_oklab a/b stays within +-0.008 of vanilla (Catacombs b may drop to -0.012 as a side
  effect of cutting the warm fill). No edits to FogBank colR/G/B or to LightScatteringBank sun colour in G3.
- **Contrast** stays within |delta| <= 0.03 (toml). Only the Blighttown ToneCorrect rows 1 and 2 move it, and
  only downward.
- **Sun (colA_s) is off in G3 except at Ash Lake (low).** The direction comes from ShadowBank, not LightBank:
  - a13 row 0 = straight down;
  - a14 row 0 = straight down;
  - a14 row 1 "From Below" (55 collisions in m14_01) = straight up.

  Strength classes follow README section 4: low = colA_s 15-25, mid = 30-33, high = 50-55 (cap reached at 58).
  - *a13:* most live rows are already 0. Set rows **0, 1, 3, 38** from 50 to 0. Row 20 (sky dome, map pieces
    only) can stay.
  - *a14:* almost every live row is at 100 (rows 7, 15 and 17 are pure red). Without a gate, the shader caps
    these to full sun.
    - **With shader gate S1** (README section 11), they become spec-only and get no sun. Then only rows
      **14 and 28** (colA_s 50, with object users) need an edit to 0.
    - **Without S1**, "off" is an active edit to 0 on rows 0, 2, 5, 6, 7, 8, 12, 14, 15, 16, 21, 22, 23, 28
      and 64, each after a water/lava A/B. Map-piece-only rows (1, 4, 17, 20, 29) can stay at vanilla.
  - *s_LightBank:* its colA_s is 100 on nearly every same-ID row, even where LightBank is 0 (for example a13
    rows 5, 14, 42). Until a capture shows which bank feeds characters' c6, also set s_LightBank colA_s to 0 on
    every row you switch off, and on every live a13 row that carries collisions or objects with sun off. Those
    rows are 5, 10, 13, 14, 19, 27, 30, 32, 39, 40 and 42. Lockstep requires this for rows whose LightBank
    value changes.
  - *Ash Lake exception:* s_LightBank 18 takes the same value as LightBank 18 (20-25), pending the c6-bank check.
- **Water conflict.** This is resolved by shader gate S1. The original analysis is kept below for the case where S1 does not land. colA_s also drives water specular, and the Water family receives no sun.
  - Water-only rows keep their vanilla colA_s: a13 rows 15 (waterfall), 16, 17, 28, 29.
  - a14 row 0 "Character Swamp" carries 383 characters plus 1 map piece, which may be the swamp water. A/B the
    swamp surface with row 0 at colA_s 0. If the wet sheen is gone, take it to the shader owner (decouple water
    specular from the sun knob). Do not leave a sun on in a cave to save it.
- **Shared rows.** a13 row 0 (every bank) spans all three m13 maps, with 949 Light and 1813 ToneMap users. a14
  row 0 is the enemy character row for both m14 maps. **a13 ToneMap and ToneCorrect row 0 stay vanilla.** The
  a13 LightBank row 0 edits are limited to sun 0 and **colA_d only** x0.85-0.9, which suits every m13 map.
  colA_u cannot move: s_LightBank 0 colA_u is 0 in vanilla, so it cannot track a ratio and lockstep fails.
- **Lockstep side effects.** Check the s_LightBank partner before moving a colA_* field:
  - a14 LightBank 2 colA_d x1.4 forces s_LightBank 2 colA_d from 80 to 112.
  - Fields that are 0 in vanilla (a13 row 10 colA_d) cannot move; the edit is a no-op.
- **Character de-sheen.** Use envDif_colA and envSpc_colA on character-only rows: a13 42, 32, 38 and a14 0, 15.
  `validate.py` lockstep ratios only cover colA_* fields, so these two are free inside the 0.5-1.5 band.
  colA_u/d on declared character rows stays in lockstep. Do not de-sheen through a13 row 0 (it carries map
  pieces).
- **Bloom.** Lava rows never go below vanilla bloom: bloomMul/bloomMulFar x1.0-1.25. Elsewhere, hold.
- **Shadow.** endDist holds at 40 and the angles are fixed. Ash Lake may use endDist x1.25-1.5 if its sun is on,
  because the sun fades out with the shadow range; check for shimmer.
- **Boundaries.** At Blighttown to the DR tunnel, Quelaag to DR, and DR to Izalith, the exposure jump must stay
  <= vanilla + 0.3 EV, and narrower is better.
- **Row mapping is inferred.** Bonfire-to-row assignments below come from row names and live-row usage, not from
  collision positions. Confirm each with a one-row tint A/B before tuning. Each area table lists the "probable"
  rows.

## 8. Blighttown (a14 / m14_00): blighttown_bridge, blighttown_swamp

**PTDE mood.** Murky and poisonous, lit by torches and the swamp glow, dark but **not crushed**. The best-sourced
G3 claim is that DSR falls to pure black where PTDE kept shadow detail (TSA; randir14). Several players find DSR
easier to see, and DSRRL deliberately keeps the murk, so the move is to lift the bottom end and keep the mood.
It is not a brightening. DSRRL found PTDE-style values removed important swamp shadows, so this uses grading, not
light-rig changes. No hue evidence: the swamp green stays.

**DSR fidelity adds.**
- Keep DSR's torch and bonfire light quality. Torch over-brightness is SFX, outside our banks.
- Reduce the whitish sheen on enemies (a14 row 0 envDif 500, envSpc 200).
- No sun: this is a cavern with no sky.

**Probable rows.**
- bridge: Light, Fog and Scatter 2 "Shadow Wait/Street"; ToneMap 2 (grayKey 0.1, minLum 0.018); ToneCorrect 2
  (contrast 1.35/1.25/1.25).
- swamp: ToneMap 1 and ToneCorrect 1 "Swamp" (contrast 1.30/1.30/1.42; brightness 0.79/0.88/0.97); Light 0
  (characters) and 2 (map).

| slug | ev | sat x | oklab a/b | clip max | crush max | extra |

6. Sun: rows 0, 2, 5, 22 and 23 are all 100, so they are spec-only under S1 and need no edit. Without S1, set them

7. Fog: hold.

**Must not change.** The swamp green (a -0.064 at the swamp), the purple-grey shanty haze, torch pools as the
landmarks, and enough murk that the depth still reads as dangerous.

## 10. Demon Ruins (a14 / m14_01): demon_ruins_1, demon_ruins_3

**PTDE mood.** No PTDE look description exists. Art intent: a hellish, ember-orange cavern with lava as the only
key light, and dark, smoky stone corridors between the lava rooms. DSRRL cut excess environment diffuse in the main
profile, then had to raise the upper ambient again because the area went too dark, so move it in small steps.
Mod 711 had to put lava bloom back for distance readability.

**DSR fidelity adds.**
- Clean lava bloom, and stone that takes the lava colour.
- *Experiment (off by default):* a red-orange underlight sun on character rows 7/15 (colA_s 20-35,
  colG_s 0..40), only where the view's ShadowBank row is 1 "From Below". It gives lava uplight with matching
  real-time shadows. Run it as a gated A/B with user sign-off. Never use it on ShadowBank row 0 (zenith) views.

## 13. Open issues for the global model

1. Water specular is tied to colA_s (section 3). This blocks a clean "sun off" on a14 row 0. **W1:** resolved as shader gate S1.
2. It is not known which bank (LightBank or s_LightBank) feeds characters' c6. One capture with LightBank = 0 and
   s_LightBank = 100 at great_hollow (row 42) would settle it.
3. Lockstep vs de-sheen: the research's strongest finding (characters over-lit) needs character rows to move
   independently of map rows. Today that is only possible through envDif_colA and envSpc_colA. Decide whether
   to keep it that way.
4. Bonfire-to-row mapping: confirm with a tint A/B (section 3).
5. A validate.py quirk: if an s_LightBank field is 0 in vanilla, the same-ID LightBank field cannot change by any
   ratio, because the unchanged s_ field reads as x1.0. This blocks a13 row 0 colA_u (reachable: 37-39 only).
   Decide whether lockstep should skip s_ fields that are zero in vanilla. **W1:** proposed as README P3.
